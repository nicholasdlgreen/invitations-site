The order page · Upload & Print

Written from scratch against the signed-off design, as a standalone page. Nothing here touches the live site. Every stage is shown open at once so the whole journey reads in one go; in use one is open and the rest are collapsed.

What this is built to: size first · the uploader straight after size and shape · six numbered steps · the range still chosen, but off the numbered line · no presets · no prices beyond the total in the bar, which the shipped bar already carries.

Signed off 30 September 2026, with these decisions folded in: step 5 is Quantity; the finishing row is Corners; the typed amount keeps its Use box and no longer spells out the range; the bar names the size and shape before the paper; step 1 keeps its existing heading; prices are not today’s question.

This file is the thing to build against. It replaced docs/WIZARD-BRIEF.md, which was deleted on 1 October: the brief described seven steps and the artwork going last, and both had been overtaken. A stale brief beside a built page is how the wrong artefact gets built from. Four standing points were carried over from it rather than lost:

  • Scope is Upload & Print. The design studio serves people who arrive without artwork and is not touched by this.
  • Admin has to drive it. Adding or removing a paper stock or a finishing option in admin must change this page, on every product, with no code change. The structure is fixed; the contents are data. A page only a developer can change will drift again.
  • One structure, every product. Variation only where a product genuinely differs — a foam board has no envelopes — never as a side effect of which price rows happen to exist.
  • No explanatory lines, and no price before the specification is finished. Wording is proposed, never shipped.

Parked, with the measurement kept in case we return to it: reading the specification out of the uploaded file. 73% of correct exports identify themselves, 95% after asking “is it folded?” — tools/test-spec-from-file.py.
